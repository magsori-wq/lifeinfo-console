— 이게 사실이면 정책 원문의 "automatically generated content without manual review or
curation"에 걸릴 소지가 있다(애드센스_정책_원문.md §1 참조).

## 절차
1. lifeinfo_db.txt에서 서로 다른 카테고리(A~G) 글 5~6편을 무작위로 골라 Blogger API로
   라이브 본문을 받아 h2/h3 헤더 골격만 추출한다(studio/blogger.py의 _svc/_blog_id/
   _post_by_path 패턴 재사용 — 이 세션이 관제탑 세션에서 A2-01·B2-04·C1-02·D1-02·F2-08
   5편을 이미 이렇게 뽑아봤다. 겹치지 않게 다른 5편으로: 예) A5-*, D3-*, E*, F4-*, G* 중에서).
2. WebSearch로 "<같은 주제> 개인 블로그 후기" 식으로 검색해 실제 티스토리/브런치/네이버
   블로그 글 3~4편을 찾아 WebFetch로 구조(헤더)와 톤을 뽑는다.
3. 대조 관점:
   - 우리 글끼리 헤더 패턴이 토씨 하나 안 틀리고 똑같은가, 아니면 주제마다 실제로 다른가
     (관제탑이 이미 본 5편은 번호 매기기·FAQ 유무·마무리 방식이 글마다 달랐다 — 완전 동일
     템플릿은 아니었다는 게 1차 소견. 이 소견을 5편 더 뽑아 검증/반박할 것)
   - 실제 개인 블로그도 인트로→본문→FAQ→마무리 구조를 쓰는지(장르 관행이면 감점 요인
     아님), 아니면 우리만 유독 기계적인지
   - 사람이 쓴 티가 나는 요소(1인칭 표현·감상·망설임·구체적 실수담)가 우리 글에는 없고
     경쟁 개인 블로그에는 있는지 — 있다면 이게 진짜 차이(E-E-A-T의 'Experience')
4. 판단은 뭉뚱그리지 말고 실측 근거(구체 인용)로 남길 것. "문제없음"이든 "문제있음"이든
   둘 다 데이터로 뒷받침해야 한다(사용자 지시: 추측 금지, 다 재기 전에 결론 말하지 말 것).
