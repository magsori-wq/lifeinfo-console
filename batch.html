     🔴 대기 중에는 이 명령을 **짧은 간격으로 다시 돌려라.** 한 번 보고 멈추지 마라.
     (관제탑도 승인 커밋을 감시하고 있지만, 네 쪽에서 확인하는 것이 확실하다)
  ⚠️ 채팅 보고는 **알림**이지 요청이 아니다. 둘 다 해도 되지만, 결재함이 없으면 요청이 아니다.

━━━ OSMU 채널 순서 — 이 순서를 바꾸지 마라 ━━━
  🔴 **발행 → 네이버 → 인스타 → 쓰레드(맨 뒤)**
     쓰레드만 **게시 후 수정이 안 된다.** 그래서 맨 뒤다 —
     앞의 것이 다 모인 뒤에 써야 한 번에 맞게 나간다.
  🔴 **캡션에는 블로그스팟과 네이버 링크를 둘 다 적는다** (2026-09-09 사장님 지시).
     네이버가 아직 없으면 그 캡션은 반쪽이다 — 그래서 네이버가 앞에 있다.
  ⛔ **네이버 게시 전에는 인스타 캡션·쓰레드 원고를 내지 않는다** (2026-09-14 결재).

     자동 기록하고, 못 찾으면 막는다. 게시 확인: `python -m studio.naverfind --gate <코드>`
     · 기다리는 동안 열려 있는 것: 인스타 카드 제작 · 쓰레드 이미지 · 다음 글 초안
     · 막히면 `batchboard now` 로 '네이버 대기' 를 남기고 다음 준비로 간다
  🔴 네이버 원문에도 「🔗 다른 채널에서도 보기」 교차링크를 넣는다 —

     그리로 가는 길이 없었다. `naver.py` 게이트가 이제 경고한다.

━━━ 열려 있는 것 — 막히지 않는다 ━━━
  ✅ **초안 작성 · 썸네일 · pubqueue 적재는 언제나 열려 있다.**
     앞 글의 4채널(네이버·쓰레드·인스타)이 안 끝났어도 **준비는 계속한다.**

  ⚠️ 앞 글의 네이버는 **사장님 손**이다(확장 차단). 그것을 기다리며
     네 일을 멈추지 마라 — 그러면 한 사람 손에 전부가 선다.


━━━ 먼저 할 것 ① — 지시·규칙을 확인하고 복창한다 ━━━

  2. 네 권한을 확인한다: python -m studio.roles

  🔴 복창이 지시서와 다르면 이부장이 바로 고친다. 복창 없이 시작하지 마라.

━━━ 먼저 할 것 ② — 네 주소를 등록한다 (10초) ━━━

      09-09 에는 3. 를 못 찾아 세션 3개에 같은 메시지를 뿌렸다.
  ⚠️ 이미 등록돼 있어도 **이름이 바뀌었으면 다시** 하라(덮어쓴다).


━━━ 브라우저를 썼으면 탭을 닫는다 ━━━

  왜: 탭이 열려 있는 동안 크롬이 창 상단에 「'Claude'에서 이 브라우저에

━━━ 막히면 ━━━
  1. 거부·실패 문구를 **한 글자도 바꾸지 말고** `batchboard now` 에 남긴다
  2. 사람 손이 필요하면 결재함에도:
     python -m studio.watch add --id blocked-topics0920cde --owner user --due <오늘> \
        --what "<무엇이 왜 막혔나>" --cmd "<사장님이 그대로 실행할 한 줄>"
  3. **그 자리에 남아 이 배치를 계속 폴링한다.** 다른 배치로 옮기지 않는다.
  4. **다른 세션(3.·이과장)의 도움이 필요하면 주소를 찾아 직접 보내지 마라.**
     `batchboard now` 의 --what 에 `🤝 <세션>에게 요청: <무엇을·왜·언제까지>` 로 남긴다.
     이부장이 그 세션 지시서로 옮기고 깨운다. 주소를 찾느라 멈추지 않는다.


━━━ 스스로 확인한다 — 관제탑이 깨워주기를 기다리지 마라 ━━━
  🔴 2026-09-07 사장님: *"이과장이 지시서를 스스로 확인하게 할 수가 없는거야?"*
     **있다.** 세션은 턴이 끝나면 잠들지만, `Monitor` 도구는 그 사이에도 돈다.
     관제탑이 승인 감시에 쓰는 그 도구를 **너도 쓸 수 있다.**

  ⚡ **지금 이 Monitor 를 걸어라** (description: 내 지시서 변경 · persistent: true):
     last=$(python -m studio.orderhash 이과장 2>/dev/null); \
     while true; do date +%s > webapp/.lee_heartbeat; \
     cur=$(python -m studio.orderhash 이과장 2>/dev/null); \
     if [ -n "$cur" ] && [ "$cur" != "$last" ]; then \
     echo "ORDER-CHANGED $last -> $cur"; last="$cur"; fi; sleep 20; done

  이 지문은 **네 앞 지시서 전부**를 요약한다. 다음 넷 중 하나만 생겨도 바뀐다:
     ① 새 지시서가 생김  ② 지시서가 갱신됨
     ③ **승인 도장이 찍힘**(사장님이 CP 에서 누르시면 자동으로 찍힌다)
     ④ 항목이 done 으로 바뀜
  이벤트가 오면 무엇이 걸렸는지 본다:  python -m studio.orderhash 이과장 --why
  🔴 이것을 걸어 두면 **관제탑이 죽어 있어도** 네가 먼저 안다.

━━━ 어긋나면 어느 쪽을 따르나 ━━━
  🔴 **지시서와 메시지가 다르면 — 나중에 갱신된 지시서가 이긴다.**

     메시지는 「보드를 읽어라」는 **깨우기**이지 지시가 아니다.
  🔴 **지시서에 「사장님이 승인하셨다」가 적혀 있으면 그것이 승인이다.**
     사장님께 다시 확인하지 마라 — 자리에 안 계시면 그 재확인으로 일이 선다.

  ⚠️ 다만 **되돌릴 수 없는 것**(라이브 발행·삭제)에 승인 표기가 없으면 물어라.
     묻지 말라는 것은 **이미 승인이 적힌 것**을 다시 묻지 말라는 뜻이다.

━━━ 이 지시서가 전부다 ━━━
  🔴 관제탑은 **메시지로 지시하지 않는다.** 채널이 둘이면 어느 것이 최신인지
     알 수 없고, 메시지는 이력에 안 남아 다음 세션이 못 본다.

     상대가 그것을 기다리며 서 있다. 못 하면 못 한다고 바로 보고한다.



━━━ 네이버 원고를 결재함에 올릴 때 ━━━

     네 다음 작업이 덮어쓴다. 실측 2026-09-07: 그렇게 올린 뒤 확인해 보니
     **제목 39자만** 남아 있었다 — 사장님이 붙여넣으셨으면 제목만 게시된다.
     같은 날 다른 한 편은 아예 **빈 껍데기**였다(--file 을 안 줘서 스켈레톤).
  ✅ `--cmd` 에 **사장님이 직접 돌릴 적재 명령**을 넣어라:
     python -m studio.pipeline naver-draft --code <코드> --file <네이버용 원고>
     그러면 누르시는 그 순간 클립보드에 들어간다. 미리 담아 두지 마라.
  🔴 `--what` 에는 **제목·카테고리·첨부 썸네일 경로·태그**를 적는다.
     🔴 첨부는 **네이버 전용 썸네일**(`thumbs_naver/<번호>n_*.png`) 이다 —

━━━ 승인 경로 (라이브를 고치기 전에 반드시) ━━━
  🔴🔴 **채팅에 미리보기를 올리고 승인을 기다리지 마라.** 그건 요청이 아니다.
     사장님이 그 창을 안 보고 계시면 **영원히 아무도 모른다** — 실측 2026-08-25.
     그리고 채팅은 이력에 안 남아 관제탑도 다음 세션도 못 본다.
  ✅ **승인은 CP 결재함으로 올린다** (2026-08-27 사장님 지시:
     *"승인요청은 항상 운영콘솔(결재함)을 통해 할 수 있도록 해!!"*)
     python -m studio.watch add --id approve-v0inject --owner user --due <오늘> \
        --what "<무엇을 어떻게 바꾸는지 · 근거 · 바뀌는 숫자>" \
        --cmd "<사장님이 그대로 실행하거나 클릭하실 완성된 한 줄>"
  🔴🔴 **네 요청은 이부장이 먼저 확인한다** (2026-09-17 사장님 지시).
     `--by 이과장` 으로 올리면 결재함이 아니라 「이부장 확인 대기」로 들어간다.
     올린 뒤 이부장을 한 줄로 깨운다: 「결재 요청 확인 부탁: watch --id <id>」
     이부장이 사실을 확인하고 처리 순서를 붙여 사장님께 올린다.
     ⚠️ 라이브 사고·되돌릴 수 없는 일처럼 급한 것만 `--urgent` 로 바로 올리고 카톡도 보낸다.
     🔴 사장님 손이 필요한 일을 **확인 없이 done 으로 닫지 마라**(09-17 쓰레드 중복 삭제 사고).
  🔴 `--what` 에 **바뀌는 내용을 실제로 적는다.** "미리보기 준비됨" 만 적으면
     사장님이 무엇을 승인하는지 모르신다 — 결재함 카드가 곧 미리보기다.
  🔴🔴 **올린 뒤 스스로 확인하라 — 승인돼도 너에게 알림이 가지 않는다.**
     2026-09-07 실측: 사장님이 14:31 에 승인하셨는데 이과장은 그대로 멈춰 있었다.
     승인은 `watch.json` 에 찍히고 커밋까지 되지만 **깨우는 배선이 없다.**
     python -m studio.watch --id approve-v0inject     ← state 가 done 이면 승인된 것
     🔴 대기 중에는 이 명령을 **짧은 간격으로 다시 돌려라.** 한 번 보고 멈추지 마라.
     (관제탑도 승인 커밋을 감시하고 있지만, 네 쪽에서 확인하는 것이 확실하다)
  ⚠️ 채팅 보고는 **알림**이지 요청이 아니다. 둘 다 해도 되지만, 결재함이 없으면 요청이 아니다.

━━━ OSMU 채널 순서 — 이 순서를 바꾸지 마라 ━━━
  🔴 **발행 → 네이버 → 인스타 → 쓰레드(맨 뒤)**
     쓰레드만 **게시 후 수정이 안 된다.** 그래서 맨 뒤다 —

  🔴 **캡션에는 블로그스팟과 네이버 링크를 둘 다 적는다** (2026-09-09 사장님 지시).
     네이버가 아직 없으면 그 캡션은 반쪽이다 — 그래서 네이버가 앞에 있다.
  ⛔ **네이버 게시 전에는 인스타 캡션·쓰레드 원고를 내지 않는다** (2026-09-14 결재).
     `osmu_manifest show/announce` · `threadsdraft` 가 네이버 RSS 로 게시를 감지해
     자동 기록하고, 못 찾으면 막는다. 게시 확인: `python -m studio.naverfind --gate <코드>`
     · 기다리는 동안 열려 있는 것: 인스타 카드 제작 · 쓰레드 이미지 · 다음 글 초안
     · 막히면 `batchboard now` 로 '네이버 대기' 를 남기고 다음 준비로 간다
  🔴 네이버 원문에도 「🔗 다른 채널에서도 보기」 교차링크를 넣는다 —
     2026-09-10 A3-12 실측 사고: 쓰레드는 게시됐는데 네이버 글에서
     그리로 가는 길이 없었다. `naver.py` 게이트가 이제 경고한다.

━━━ 열려 있는 것 — 막히지 않는다 ━━━
  ✅ **초안 작성 · 썸네일 · pubqueue 적재는 언제나 열려 있다.**
     앞 글의 4채널(네이버·쓰레드·인스타)이 안 끝났어도 **준비는 계속한다.**

     즉 **막는 것은 발행뿐**이다(코드: pipeline.py 0b-6 `if a.publish:`).
  ⚠️ 앞 글의 네이버는 **사장님 손**이다(확장 차단). 그것을 기다리며
     네 일을 멈추지 마라 — 그러면 한 사람 손에 전부가 선다.


━━━ 먼저 할 것 ① — 지시·규칙을 확인하고 복창한다 ━━━

  3. **복창 보고** — 일을 시작하기 전에 한 줄로:

  🔴 복창이 지시서와 다르면 이부장이 바로 고친다. 복창 없이 시작하지 마라.

━━━ 먼저 할 것 ② — 네 주소를 등록한다 (10초) ━━━
  🔴 `ListAgents` 를 한 번 돌려 **첫 줄의 네 표시명**을 확인한 뒤:

  왜: 이름은 세션을 재개할 때마다 바뀐다. 관제탑이 그걸 알 방법이 없어
      09-03 에 이과장 앞 지시를 **32시간** 엉뚱한 곳에 보냈고,
      09-09 에는 3. 를 못 찾아 세션 3개에 같은 메시지를 뿌렸다.
  ⚠️ 이미 등록돼 있어도 **이름이 바뀌었으면 다시** 하라(덮어쓴다).

  왜: 탭이 열려 있는 동안 크롬이 창 상단에 「'Claude'에서 이 브라우저에

━━━ 막히면 ━━━
  1. 거부·실패 문구를 **한 글자도 바꾸지 말고** `batchboard now` 에 남긴다
  2. 사람 손이 필요하면 결재함에도:
     python -m studio.watch add --id blocked-v0inject --owner user --due <오늘> \
        --what "<무엇이 왜 막혔나>" --cmd "<사장님이 그대로 실행할 한 줄>"
  3. **그 자리에 남아 이 배치를 계속 폴링한다.** 다른 배치로 옮기지 않는다.
  4. **다른 세션(3.·이과장)의 도움이 필요하면 주소를 찾아 직접 보내지 마라.**
     `batchboard now` 의 --what 에 `🤝 <세션>에게 요청: <무엇을·왜·언제까지>` 로 남긴다.
     이부장이 그 세션 지시서로 옮기고 깨운다. 주소를 찾느라 멈추지 않는다.


━━━ 스스로 확인한다 — 관제탑이 깨워주기를 기다리지 마라 ━━━
  🔴 2026-09-07 사장님: *"이과장이 지시서를 스스로 확인하게 할 수가 없는거야?"*
     **있다.** 세션은 턴이 끝나면 잠들지만, `Monitor` 도구는 그 사이에도 돈다.
     관제탑이 승인 감시에 쓰는 그 도구를 **너도 쓸 수 있다.**

  ⚡ **지금 이 Monitor 를 걸어라** (description: 내 지시서 변경 · persistent: true):
     last=$(python -m studio.orderhash 이과장 2>/dev/null); \
     while true; do date +%s > webapp/.lee_heartbeat; \
     cur=$(python -m studio.orderhash 이과장 2>/dev/null); \
     if [ -n "$cur" ] && [ "$cur" != "$last" ]; then \
     echo "ORDER-CHANGED $last -> $cur"; last="$cur"; fi; sleep 20; done

  이 지문은 **네 앞 지시서 전부**를 요약한다. 다음 넷 중 하나만 생겨도 바뀐다:
     ① 새 지시서가 생김  ② 지시서가 갱신됨
     ③ **승인 도장이 찍힘**(사장님이 CP 에서 누르시면 자동으로 찍힌다)
     ④ 항목이 done 으로 바뀜
  이벤트가 오면 무엇이 걸렸는지 본다:  python -m studio.orderhash 이과장 --why
  🔴 이것을 걸어 두면 **관제탑이 죽어 있어도** 네가 먼저 안다.

━━━ 어긋나면 어느 쪽을 따르나 ━━━
  🔴 **지시서와 메시지가 다르면 — 나중에 갱신된 지시서가 이긴다.**
     판정은 보드의 `order_at`(등록 시각)으로 한다. 기억으로 고르지 마라.
     메시지는 「보드를 읽어라」는 **깨우기**이지 지시가 아니다.
  🔴 **지시서에 「사장님이 승인하셨다」가 적혀 있으면 그것이 승인이다.**
     사장님께 다시 확인하지 마라 — 자리에 안 계시면 그 재확인으로 일이 선다.
     실측 2026-09-10: 제휴 링크 하나를 재확인하느라 다음 글 발행 전체가 섰다.
  ⚠️ 다만 **되돌릴 수 없는 것**(라이브 발행·삭제)에 승인 표기가 없으면 물어라.
     묻지 말라는 것은 **이미 승인이 적힌 것**을 다시 묻지 말라는 뜻이다.

━━━ 이 지시서가 전부다 ━━━
  🔴 관제탑은 **메시지로 지시하지 않는다.** 채널이 둘이면 어느 것이 최신인지
     알 수 없고, 메시지는 이력에 안 남아 다음 세션이 못 본다.
     새 지시는 이 배치의 지시서가 **갱신되는 것**으로만 온다.
     python -m studio.batchboard order --id v0inject

     while true; do date +%s > webapp/.lee_heartbeat; \

     if [ -n "$cur" ] && [ "$cur" != "$last" ]; then \
     echo "ORDER-CHANGED $last -> $cur"; last="$cur"; fi; sleep 20; done
