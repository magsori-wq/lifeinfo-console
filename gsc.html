📌 색인요청 사용법 (순서대로)
⚠️ 핵심 (2026-07-28 정정) — 색인 요청은 클린 URL(?m=1 없는 주소)로 합니다. 예전 안내는 "반드시 ?m=1"이었으나 그 전제가 사라졌습니다: 실측 결과 리디렉션 오류 0편이고, 클린 URL 로 검사한 7편이 “색인됨”으로 확인됩니다. ?m=1로 요청하면 모바일 대체 주소를 등록하게 됩니다.
  1. [미요청만] 필터로 아직 요청 안 한 글만 봅니다.
  2. 각 줄 [GSC 검사] 클릭 → GSC 열림 + 클린 URL 자동 복사 → GSC 상단 검사창에 붙여넣기(Ctrl+V)+Enter
  3. 실제 URL 테스트 → "URL을 Google에 등록할 수 있음"(초록) 확인 → 파란 ‘색인 생성 요청’ 클릭 → “색인 생성을 요청했습니다” 팝업 확인.
  4. 콘솔로 돌아와 그 줄 ‘완료’를 직접 체크 — 실제로 요청한 글만 체크.
  5. 하루 약 10건 한도가 있어 초과 시 "할당량 초과"가 뜹니다 → 나눠서 진행.
  6. 실제 색인 여부(✅색인/⏳발견/⚠️리다이렉트/⛔미발견)는 며칠 뒤 PC에서 searchconsole.py inspect → deploy 하면 색인상태 칸에 갱신됩니다.
※ 완료 체크는 자동이 아니라 직접 합니다(구글은 요청 여부를 외부에 안 알려줌). 예전에 조회만 하고 체크된 게 있으면 아래 [체크 초기화]로 지우고 다시 정확히 관리하세요.
❓ ‘미발견 / 리다이렉트’는 왜 뜨고, 어떻게 하나요?
⛔ 미발견(URL unknown) = 구글이 아직 크롤을 안 해서 모른다는 뜻(요청을 눌렀어도 처리 전엔 이렇게 보입니다). 신규 블로그는 크롤이 느립니다.
⚠️ 리다이렉트(Redirect error) = 고장이 아닙니다 — 블로그스팟은 모바일 접속 시 ?m=1로 302 이동하고, 구글은 모바일 우선으로 크롤하므로 이 표시가 뜹니다. Blogger 커뮤니티 Product Expert 답변(스레드↗, 2026-08-04 원문 확인): “실제 오류가 아니라 검색 콘솔의 표시 오류”이고 “It comes and goes on its own”(저절로 생겼다 없어진다). 처방은 커스텀 robots.txt 제거(우리는 기본값이라 해당 없음)와 콘텐츠 품질·홍보이지 기술이 아닙니다.
※ 2026-08-04 실측으로 기술 원인 9개를 지웠습니다 — 페이지 내 리디렉션 코드 없음 · canonical 정확 · 맞춤 리디렉션 5건 무해 · 사이트맵 171건 전수 · robots.txt 기본값 · X-Robots-Tag: all · 맞춤 도메인 없음 · 수동 조치 없음 · 페이지 무게가 색인된 글과 동일 · 별도 모바일 테마 없음(isMobile:false / isMobileRequest:true). 다시 기술을 의심하지 마세요.
※ 다만 SERVER_ERROR·NOT_FOUND·차단은 표시 오류가 아니라 진짜 이상입니다. 위 크롤 건강 배너가 그 둘을 갈라서 보여줍니다.
✅ 색인 요청은 클린 URL로 — 클린 URL 로 검사한 7편이 “Submitted and indexed”로 확인됩니다(A2-01·B1-01·D1-01·D1-02·D3-03·F2-08·H1-01, 2026-07-28 실측). ?m=1로 요청하면 색인시키려는 주소가 아니라 모바일 대체 주소를 등록하게 됩니다. 커뮤니티에 “?m=1을 제출하라”는 조언이 돌지만 필수가 아니고(원문도 “optionally”), 우리 실측은 클린 URL 쪽입니다.
※ 정확히 말하면 index_status.json은 우리가 제출한 URL(클린)과 그 판정만 담습니다 — 구글이 고른 대표주소(google-selected canonical) 필드는 없습니다. 위 문장은 “클린 URL 로 물었더니 색인됨이라고 답했다”까지가 실측 범위입니다.
그 외 = 시간(신규 2~6주) · 트래픽/백링크(OSMU) · 꾸준한 발행.
※ 재요청은 크롤을 부르지만 색인을 만들지는 못합니다 — 2026-08-04 대조 실험: 5편을 요청하니 당일 1편 크롤·1편 Discovered 이동, 같은 시각 대조군 8편은 8/8 무변화였습니다. 즉 요청 자체는 듣습니다. 다만 크롤된 130편 중 색인은 5편이라 진짜 벽은 색인 판정이고, 그 레버는 본문 원본가치·OSMU 유입·시간입니다. / ?m=1 테마 스크립트 강제 제거·커스텀 도메인은 권장하지 않음(우리는 이미 반응형 단일 테마).

📝 검색 설명 입력 방법
왜 넣나 — 문구 1개가 태그 2개를 채웁니다(2026-07-28 실측): 검색결과 스니펫 meta description + 카톡·쓰레드 링크 공유 미리보기 og:description. 안 넣으면 og 가 161편 전부 같은 블로그 공통문구로 뜹니다.
  1. [문구 복사] 클릭 → 클립보드에 들어갑니다.
  2. [편집화면↗] 클릭 → 그 글 편집기가 바로 열립니다(글 목록에서 찾을 필요 없음).
  3. 오른쪽 글 설정 → 검색 설명 펼치기 → 입력칸에 Ctrl+V.
  4. 오른쪽 위 [업데이트] 클릭 ← 이걸 눌러야 저장됩니다.
  5. 반영 확인은 python -m studio.seodesc scan → deploy. 체크박스는 없습니다 — 라이브를 실제로 긁어서 판정합니다.
※ Blogger API 는 검색 설명을 읽지도 쓰지도 못합니다(2026-07-28 실측). 그래서 이 작업만은 자동 발행 경로로 안 되고, 편집화면에서 넣어야 합니다. 입력 상한 150자, 권장 70~120자.

🔄 색인 재요청 — 구글이 아직 못 본 글만
1순위가 왜 '미크롤'인가 (2026-08-04 실측) — 색인 대기 중 35편은 구글이 URL 존재 자체를 모릅니다(URL is unknown to Google). 사이트맵에는 171건 전수 등재돼 있고, 7/30 이후 요청분은 100% 크롤됐습니다. 즉 7/14~7/27 요청분만 통째로 유실된 것이라, 이건 "같은 걸 또 들이미는" 요청이 아니라 처음 알리는 요청입니다.
🔴 다만 기대치를 낮추세요 — 이미 한 번 해봤고 결과가 나빴습니다. 2026-07-29 에 10편을 재요청했는데, 6일 뒤 실측(8/4)에서 크롤된 건 1편(D1-01)뿐입니다. 나머지 9편은 마지막 크롤이 전부 재요청 이전이거나 없습니다. 그때 미크롤이던 2편 중 1편은 여전히 unknown, 1편은 Discovered로만 이동했습니다 (구글이 알게는 됐으나 안 옴). 재요청은 재크롤을 앞당기는 약한 신호이고, 진짜 레버는 여전히 OSMU 유입·원본가치·시간입니다.
⚠️ 전량 요청 금지. 예전에 고친 것 없이 전량 요청했다가 Coverage 에 유효성 검사: 실패함이 찍혔습니다. 여기 뜬 줄만 하루 한도(약 10건)에 맞춰. 회색 줄은 일부러 잠근 것이라 누르면 안 됩니다.
  1. 각 줄 [검사창↗] 클릭 → 그 글의 GSC 검사 화면이 바로 열립니다(붙여넣기 불필요)
  2. 거기서 색인 생성 요청 클릭
  3. 그 줄 완료 체크 → 아래 [기록 명령 복사] → 터미널에 붙여넣기(파일에 남습니다)
  4. 판정은 python -m studio.crawl_watch 가 매일 밤 자동으로 합니다
※ 목록은 python -m studio.reindex --emit 이 만듭니다. 🔴 색인 요청은 API가 없습니다(URL 검사 API는 읽기 전용, Indexing API는 채용공고·방송 전용) — 누르는 것은 사람이고, 이 화면은 클릭을 최단으로 줄이고 기록을 자동화할 뿐입니다.
