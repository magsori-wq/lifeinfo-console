# 화면 없이 조작하기 — 피드백 채널 만들기

블라인드 타이핑의 문제는 **결과를 알 수 없다**는 것이다. 명령이 실행됐는지, 오타가 났는지,
UAC 창에서 막혔는지 구분이 안 되면 시도 자체가 무의미하다.
그래서 먼저 **소리**와 **로그 파일**, 두 개의 피드백 채널을 만든다.

---

## 방법 1 — 내레이터로 소리 채널 만들기 (준비물 없음, 30초)

Windows 내레이터는 **화면 내용을 소리로 읽어준다**. 이게 유일하게 즉시 쓸 수 있는 피드백이다.

1. 전원을 켜고 **2분** 기다린다.
2. `Ctrl + Win + Enter` 를 누른다 (내레이터 토글).

### 들리는 소리로 상태를 판별한다

| 들리는 것 | 의미 |
|---|---|
| 시작음 + 음성이 나온다 | **정상 모드로 부팅됨.** 오디오 드라이버가 살아 있다. 아래 3번으로 |
| 아무 소리도 없다 | **안전모드일 가능성이 높다.** 안전모드는 오디오 드라이버를 로드하지 않아 내레이터가 소리를 못 낸다 |
| 소리는 나는데 음성이 아니라 삑 소리만 | 내레이터가 아직 로딩 중. 30초 더 기다려라 |

> 이 판별이 중요하다. **안전모드에서는 외부 모니터를 살릴 방법이 아예 없다**(다중 디스플레이
> 투사가 비활성화됨). 소리가 안 난다면 화면을 살리는 시도 대신 안전모드 탈출이 먼저다.

3. 음성이 들린다면, 내레이터가 읽어주는 것을 들으며 조작할 수 있다:
   - `Win + R` → `DisplaySwitch.exe /clone` → `Enter`
   - 내레이터가 실행 결과를 읽어준다. 오타가 났으면 "찾을 수 없습니다" 류가 들린다.
4. 끌 때는 다시 `Ctrl + Win + Enter`.

---

## 방법 2 — USB 스크립트 + 로그 회수 (가장 확실함)

소리로도 판단이 안 되면 이 방법을 쓴다. **결과를 파일로 남겨 다른 PC에서 읽는다.**

### 준비 (다른 PC에서)

1. USB 메모리를 꽂는다.
2. 이 저장소의 `restore/fix.bat` 를 **USB 최상위(루트)** 에 복사한다.
   - 다운로드: https://github.com/magsori-wq/lifeinfo-console/blob/claude/remote-pc-control-u1wlbw/restore/fix.bat
   - 우측 상단 **Download raw file** 버튼 → 저장 → USB 루트에 `fix.bat` 로 둔다.
   - 경로가 `E:\fix.bat` 처럼 **루트**여야 한다. 폴더 안에 넣지 마라.
3. USB를 뽑아 노트북에 꽂는다.

### 실행 (노트북, 블라인드)

1. 노트북 전원을 켜고 **2분** 대기 → 비밀번호 + `Enter` → 다시 **1분** 대기.
2. `Win + R` 을 누르고 아래를 타이핑한 뒤 `Enter`:
   ```
   d:\fix.bat
   ```
3. **소리를 들어라.** 삑 소리 1번 = 스크립트를 찾아서 시작했다.
   - 아무 소리도 없으면 드라이브 문자가 틀린 것이다. `Win + R` 로 `e:\fix.bat`,
     `f:\fix.bat`, `g:\fix.bat` 를 차례로 시도하라.
     **틀린 문자를 입력해도 아무 일도 일어나지 않는다.** 마음껏 시도해도 된다.
4. 이 시점에서 **약 20초간 진단과 화면 전환이 이미 실행된다** (관리자 권한 불필요).
5. 낮고 긴 삑 소리 → 관리자 권한 요청(UAC)이 뜬 것이다. **`Alt + Y`**.
6. 삑 소리 2번(올라가는 음) = 관리자 권한 획득. **약 40초 기다린다.**
7. 삑 소리 3번(마지막이 길게) = **완료**.

### 결과 확인

8. 전원 버튼을 **짧게 한 번** 눌러 정상 종료한다 (길게 누르지 마라).
9. USB를 뽑아 다른 PC에 꽂는다. **로그가 두 개** 생겼을 수 있다:

| 파일 | 의미 |
|---|---|
| `fix_log.txt` | 관리자 권한 **없이** 실행된 1차 패스. 진단·화면전환은 전부 여기 들어 있다 |
| `fix_log_admin.txt` | 관리자 권한으로 실행된 2차 패스. 안전모드 해제·원격데스크톱·전원설정 포함 |

10. **두 파일 모두** Claude에게 붙여넣는다.

### 로그 조합으로 무엇을 알 수 있나

- **둘 다 있음** → 정상 완료. 로그를 읽고 다음 단계를 정한다.
- **`fix_log.txt` 만 있음** → UAC 프롬프트가 수락되지 않았다. 다시 실행하고 `Alt + Y`.
  단 **화면 전환과 진단은 이미 됐으므로** 이 파일만으로도 원인 판별이 가능하다.
- **둘 다 없음** → 스크립트가 실행되지 않았다. 드라이브 문자가 틀렸거나 로그인이
  안 된 상태다. 3~4단계를 다른 문자로 다시.

이게 1차 패스를 권한 없이 도는 이유다. **UAC를 놓쳐도 진단 정보는 확보된다.**

### 삑 소리가 전혀 안 들리는 경우

스피커가 음소거이거나 안전모드로 오디오 드라이버가 없는 상태다.
그래도 스크립트는 실행됐을 수 있으니 **3분 기다린 뒤** 8~10단계로 로그를 확인하라.
**로그 파일의 존재 여부가 최종 판단 근거다** — 소리는 보조 수단일 뿐이다.

### 계정이 표준 사용자라면

`Alt + Y` 로 안 넘어가고 **관리자 아이디·비밀번호를 요구**하는 경우가 있다.
이때는 블라인드로 자격증명을 타이핑해야 하므로 난이도가 크게 올라간다.
`fix_log.txt` 만 확보하고 넘어가라 — 그것으로도 판별은 된다.

## fix.bat 가 하는 일

**여러 번 실행해도 안전하고, 사용자 데이터를 지우지 않는다.**
그리고 **내장 패널을 비활성화하지 않는다** — 그건 로그를 읽고 필요하다고 판단된 뒤에
별도로 할 일이다.

**1차 패스 (관리자 권한 불필요)** → `fix_log.txt`
1. Windows 에디션 기록 (RDP 호스트는 Pro 이상에서만 가능)
2. **안전모드 여부 판정** — `BootupState` 가 `Normal boot` / `Fail-safe boot`
3. 그래픽 어댑터·드라이버·현재 해상도
4. **Windows가 인식하는 모니터 전부** ← 가장 중요한 진단.
   EDID, PnP 장치 상태, 그리고 실제 화면 경계(`Screen.AllScreens`)까지 3중으로 기록
5. `DisplaySwitch /clone` → `/external` 순서로 출력 전환 시도, 각 단계 후 해상도 재기록

**2차 패스 (관리자 권한)** → `fix_log_admin.txt` — 위 전부 + 아래
6. **안전모드 플래그 제거** (`bcdedit /deletevalue safeboot`)
7. **원격 데스크톱 활성화** + 방화벽 허용 + 서비스 자동시작
   (NLA는 의도적으로 **켜둔 채**로 남긴다. 접속이 실제로 거부될 때만 손댈 것)
8. **IP 주소·호스트명·로컬 계정 목록** — 다른 PC에서 RDP로 접속할 정보
9. 덮개 닫을 때 동작을 "아무 것도 하지 않음"으로
10. `C:\lifeinfo` 및 `studio\`·`posts\` 등 존재 여부와 파일 수

### 로그에서 무엇을 보게 되는가

가장 결정적인 항목은 **[4] 모니터 목록**이다.

- **모니터·화면이 2개** 나오면 → 외부 모니터가 **이미 인식되고 있다**. 순전히 어느 쪽으로
  출력하느냐의 문제이고 소프트웨어로 해결된다. 이 경우 내장 패널을 장치 수준에서
  비활성화해 외부를 유일한 출력으로 만드는 방법이 확실하다(로그 확인 후 진행).
- **모니터가 1개**(내장 패널)뿐이면 → 외부 출력이 초기화되지 않는 것이다. 다른 포트를
  시도하고, 그래도 안 되면 `DISPLAY_RECOVERY.md` 의 C경로(내장 패널 케이블 분리)로 간다.
  **이 경우 내장 패널을 비활성화하면 표시 장치가 0개가 되므로 절대 하지 마라.**

그리고 **[8] IP 주소**가 나오고 Windows가 Pro 이상이면, 다음부터는 다른 PC에서
`mstsc` 로 접속해 **정상 화면으로** 작업할 수 있다. 그게 이 모든 과정의 목표다.
Home 에디션이면 RDP 호스트가 불가능하므로 이 경로는 막힌다 — 로그의 [1] 항목으로 확인된다.

## 주의 — 강제 종료를 반복하지 마라

전원 버튼을 **길게 눌러** 강제 종료하는 것을 3회 연속 반복하면 Windows가 부팅 실패로
판단해 복구 환경(WinRE)으로 진입한다. WinRE도 같은 디스플레이 문제를 겪으므로
상황이 더 복잡해질 뿐이다. 종료는 전원 버튼을 **짧게 한 번** 눌러라(정상 종료 신호).

## 이것들이 모두 실패하면

`DISPLAY_RECOVERY.md` 의 C경로로 간다. 요약하면:

- **C-1**: 내장 패널 eDP 케이블을 분리한다 → 외부 모니터가 유일한 출력이 되어 자동으로
  주 디스플레이가 된다. 확실한 해법. 분해가 부담되면 서비스센터에 "내장 패널 케이블
  분리만" 요청하면 된다.
- **C-2**: SSD를 빼서 USB 외장 케이스에 넣고 다른 PC에 연결 → `C:\lifeinfo` 통째로 복사.
  화면 문제를 완전히 우회하며, **작업 재개가 급하다면 이게 최단 경로다.**
  BitLocker가 걸려 있으면 복구 키가 필요하다:
  https://account.microsoft.com/devices/recoverykey

특히 `studio\` 는 GitHub에 백업이 없으므로, 디스크가 읽히는 동안 이것부터 확보하는 것이
최우선이다.
