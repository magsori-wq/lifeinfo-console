# 화면 없이 조작하기 — 피드백 채널 만들기

블라인드 타이핑의 문제는 **결과를 알 수 없다**는 것이다. 명령이 실행됐는지, 오타가 났는지,
UAC 창에서 막혔는지 구분이 안 되면 시도 자체가 무의미하다.
그래서 먼저 **소리**와 **로그 파일**, 두 개의 피드백 채널을 만든다.

---

## 방법 1 — 내레이터로 소리 채널 만들기 (준비물 없음, 30초)

Windows 내레이터는 **화면 내용을 소리로 읽어준다**. 이게 유일하게 즉시 쓸 수 있는 피드백이다.

1. 전원을 켜고 **2분** 기다린다.
2. `Ctrl + Win + Enter` 를 누른다 (내레이터 토글).

### 들리는 소리로 상태를 판별한다

| 들리는 것 | 의미 |
|---|---|
| 시작음 + 음성이 나온다 | **정상 모드로 부팅됨.** 오디오 드라이버가 살아 있다. 아래 3번으로 |
| 아무 소리도 없다 | **안전모드일 가능성이 높다.** 안전모드는 오디오 드라이버를 로드하지 않아 내레이터가 소리를 못 낸다 |
| 소리는 나는데 음성이 아니라 삑 소리만 | 내레이터가 아직 로딩 중. 30초 더 기다려라 |

> 이 판별이 중요하다. **안전모드에서는 외부 모니터를 살릴 방법이 아예 없다**(다중 디스플레이
> 투사가 비활성화됨). 소리가 안 난다면 화면을 살리는 시도 대신 안전모드 탈출이 먼저다.

3. 음성이 들린다면, 내레이터가 읽어주는 것을 들으며 조작할 수 있다:
   - `Win + R` → `DisplaySwitch.exe /clone` → `Enter`
   - 내레이터가 실행 결과를 읽어준다. 오타가 났으면 "찾을 수 없습니다" 류가 들린다.
4. 끌 때는 다시 `Ctrl + Win + Enter`.

---

## 방법 2 — USB 스크립트 + 로그 회수 (가장 확실함)

소리로도 판단이 안 되면 이 방법을 쓴다. **결과를 파일로 남겨 다른 PC에서 읽는다.**

### 준비 (다른 PC에서)

1. USB 메모리를 꽂는다.
2. 이 저장소의 `restore/fix.bat` 를 **USB 최상위(루트)** 에 복사한다.
   - 다운로드: https://github.com/magsori-wq/lifeinfo-console/blob/claude/remote-pc-control-u1wlbw/restore/fix.bat
   - 우측 상단 **Download raw file** 버튼 → 저장 → USB 루트에 `fix.bat` 로 둔다.
   - 경로가 `E:\fix.bat` 처럼 **루트**여야 한다. 폴더 안에 넣지 마라.
3. USB를 뽑아 노트북에 꽂는다.

### 실행 (노트북, 블라인드)

1. 노트북 전원을 켜고 **2분** 대기 → 비밀번호 + `Enter` → 다시 **1분** 대기.
2. `Win + R` 을 누르고 아래를 타이핑한 뒤 `Enter`:
   ```
   d:\fix.bat
   ```
3. **소리를 들어라.** 삑 소리 1번 = 스크립트가 시작됐다.
   - 아무 소리도 없으면 드라이브 문자가 틀린 것이다. `Win + R` 로 `e:\fix.bat`,
     `f:\fix.bat`, `g:\fix.bat` 를 차례로 시도하라. **틀린 문자를 입력해도 아무 일도 안 생긴다.**
4. 낮고 긴 삑 소리가 나면 → 관리자 권한 요청(UAC)이 뜬 것이다. **`Alt + Y`** 를 눌러라.
5. 삑 소리 2번(높아지는 음)이 들리면 관리자 권한으로 실행 중이다. **약 40초 기다린다.**
6. 삑 소리 3번(마지막이 길게)이 들리면 **완료**다.

### 결과 확인

7. 전원을 정상적으로 끈다 — 전원 버튼을 **짧게 한 번** 누른다(길게 누르지 마라).
8. USB를 뽑아 다른 PC에 꽂고 **`fix_log.txt`** 를 연다.
9. 그 내용을 Claude에게 붙여넣는다.

### 삑 소리가 전혀 안 들리는 경우

노트북 스피커가 음소거이거나 안전모드로 오디오가 없는 상태다. 그래도 스크립트는
실행됐을 수 있으니 **일단 3분 기다린 뒤** 7~9단계로 로그를 확인해 보라.
`fix_log.txt` 가 USB에 생겼다면 실행된 것이다. 파일이 없으면 실행되지 않은 것이다.

## fix.bat 가 하는 일

로그를 남기면서 순서대로 처리한다. **여러 번 실행해도 안전하고, 사용자 데이터를 지우지 않는다.**

1. 관리자 권한으로 자기 자신을 재실행 (UAC)
2. Windows 에디션 기록 (RDP 호스트는 Pro 이상에서만 가능)
3. **안전모드 여부 판정** — `BootupState` 가 `Normal boot` 인지 `Fail-safe boot` 인지
4. **안전모드 플래그 제거** (`bcdedit /deletevalue safeboot`)
5. 그래픽 어댑터 목록·드라이버·현재 해상도 기록
6. **Windows가 인식하는 모니터 전부 기록** ← 가장 중요한 진단
7. `DisplaySwitch /clone` → `/external` 순서로 출력 전환 시도, 각 단계 후 해상도 기록
8. **원격 데스크톱 활성화** + 방화벽 허용 + 서비스 시작
9. **IP 주소·호스트명 기록** — 다른 PC에서 RDP로 접속할 주소
10. 덮개 닫을 때 동작을 "아무 것도 하지 않음"으로
11. `C:\lifeinfo` 및 `studio\`·`posts\` 존재 여부와 파일 수 기록

### 로그에서 무엇을 보게 되는가

가장 결정적인 항목은 **[5] 모니터 목록**이다.

- **모니터가 2개** 나오면 → 외부 모니터가 **이미 인식되고 있다**. 순전히 출력 전환 문제이고
  소프트웨어로 해결된다.
- **모니터가 1개**(내장 패널)뿐이면 → 외부 출력이 초기화되지 않는 것이다. 다른 포트를
  시도하거나 `DISPLAY_RECOVERY.md` 의 C경로(내장 패널 케이블 분리)로 간다.

그리고 **[8] IP 주소**가 나오고 Windows가 Pro 이상이면, 다음부터는 다른 PC에서
`mstsc` 로 접속해 **정상 화면으로** 작업할 수 있다. 그게 이 모든 과정의 목표다.

## 주의 — 강제 종료를 반복하지 마라

전원 버튼을 **길게 눌러** 강제 종료하는 것을 3회 연속 반복하면 Windows가 부팅 실패로
판단해 복구 환경(WinRE)으로 진입한다. WinRE도 같은 디스플레이 문제를 겪으므로
상황이 더 복잡해질 뿐이다. 종료는 전원 버튼을 **짧게 한 번** 눌러라(정상 종료 신호).

## 이것들이 모두 실패하면

`DISPLAY_RECOVERY.md` 의 C경로로 간다. 요약하면:

- **C-1**: 내장 패널 eDP 케이블을 분리한다 → 외부 모니터가 유일한 출력이 되어 자동으로
  주 디스플레이가 된다. 확실한 해법. 분해가 부담되면 서비스센터에 "내장 패널 케이블
  분리만" 요청하면 된다.
- **C-2**: SSD를 빼서 USB 외장 케이스에 넣고 다른 PC에 연결 → `C:\lifeinfo` 통째로 복사.
  화면 문제를 완전히 우회하며, **작업 재개가 급하다면 이게 최단 경로다.**
  BitLocker가 걸려 있으면 복구 키가 필요하다:
  https://account.microsoft.com/devices/recoverykey

특히 `studio\` 는 GitHub에 백업이 없으므로, 디스크가 읽히는 동안 이것부터 확보하는 것이
최우선이다.
