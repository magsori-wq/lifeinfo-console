2. 원인 묶음 (왜 반복되나)

1. 쓰는 길이 여럿 — batch.json·watch.json 을 CLI·결재서버·today·towertick 이 각자 쓴다 → 유실·되돌림.

2. 세는 곳이 여럿 — 결재 건수 4곳, 상시 판정 3곳, 멈춤 수 3곳 → 화면끼리 다른 숫자.

3. 파일이 계속 커진다 — 끝난 것을 안 치움 → 느림 → 경합 창 확대 → push 과다.

4. 같은 사실을 여러 문서에 적음 — 세션 ID·게시 주체·모드 날짜 → 한쪽만 고쳐 낡음.

5. 확인 절차가 사람 기억에 의존 — 단정 보고·이음매 정체는 코드 신호를 만들 때마다 줄었다(설계도 방식이 유효).

3. CP 데이터 로직 개선 플랜 (준비안 — 착수는 사장님 결재 뒤)

원칙: ① 쓰는 길 하나(batch.json·watch.json 쓰기는 잠금+원자적 쓰기 한 함수만) ② 세는 곳 하나(파이썬 판정 → 구운 파일 → 화면은 그리기만) ③ 화면용 작은 파일(열린 것만).

순서 원칙: 사고(유실) 막는 것 → 숫자 일치 → 가볍게. 각 단계는 설계도 마디 먼저(엔진설계도 「쓰는 법」), 고친 뒤 페이블 검증·테스트.
